Where FPAS spends its time

A read-only investigation of the Rust runtime, its measured slow paths, and architectural options ranging from a leaner interpreter to a replaceable runtime core.

Outcome first: controlled follow-up work confirmed five interpreter improvements. Separating normal and debug dispatch produced a smaller broad win; borrowing scalar operands removed reference-count churn; direct typed integer handlers improved branch_dispatch by 10.2–12.8%; direct intrinsic ownership routing improved mixed intrinsic dispatch by 14.0–14.1%; and direct cached callback loading improved array_callbacks by 23.9–24.1%. Two current-worker callback-frame designs were slower by 21.5% and 41.4%. The bounded trusted-image probes also missed the broad 5% gate. All failed designs were rolled back; Stage 6 single-worker globals are next.

Scope and constraints

  • The initial audit was read-only; follow-up work changed only Rust VM internals and performance documentation.
  • The accepted changes passed release builds, the complete workspace test suite, and controlled full-suite benchmarks.
  • Absolute benchmark times are machine-specific; the reported improvements use same-checkout before/after comparisons.
  • FPAS syntax and semantics are held fixed. Rust internals, bytecode, runtime values, compiler/runtime seams, and artifact formats may be replaced.
  • Every speed claim in the solution reports is a hypothesis until it passes the project workflow: save baseline, change one variable, release build, compare the full relevant suite, then record only a settled win.

Recommended reading

Start with the audit for the original evidence, then use the fast-interpreter status table as the progress record for completed work, rejected probes, and remaining proposals. Continue with Stage 6 global-storage isolation. Do not repeat trusted branch targets, the opcode mirror, infallible fetch, callback-resolution caching, or current-worker callback frames unchanged. Return to typed real operations only after adding a benchmark that isolates them. Consider compact bytecode, heap, or JIT work only through the rewrite evidence gates.
